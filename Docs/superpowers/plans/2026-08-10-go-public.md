# Go Public — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the DevCanopy tree safe and welcoming to publish at
`cpmadrid/devcanopy` — CI off the self-hosted fleet, no Sassy-Dog defaults or
private network topology in shipped code, and a public-facing document set.

**Architecture:** Seven code tasks land on a private repo and are validated by
CI before any visibility change. The irreversible GitHub operations (repo
creation, visibility flip, archive) are a separate gated runbook at the end,
executed by a human, never by a task runner.

**Tech Stack:** Rust (workspace: `crates/*`, `app/src-tauri`), GitHub Actions,
Tauri v2.

**Spec:** `Docs/superpowers/specs/2026-08-10-go-public-design.md`

## Global Constraints

- Toolchain is pinned by the root `rust-toolchain.toml`. Do not change it.
- Every task must leave `./dev lint` clean — that is `cargo fmt --all -- --check`
  plus `cargo clippy --locked --workspace --all-targets -- -D warnings`.
  Warnings are errors.
- Every task must leave `./dev test` green — `cargo test --locked --workspace`
  plus the `tests/frontend` Playwright suite.
- Conventional commits: `feat:`, `fix:`, `chore:`, `docs:`.
- **Never fabricate a value in the UI.** Unknown renders `—`. A defaulted state
  is as much a fabrication as a defaulted number.
- The Swift app under `DevCanopy/` is frozen and absent from CI. Mirror changes
  into it only where this plan says so, and never rely on it to compile.
- Do not touch the bundle identifier, the keychain service name
  (`com.sassydog.devcanopy`), or `APP_DIR_NAME`. Changing them orphans live
  credentials for zero user benefit.
- **No task in this plan creates, publishes, transfers, or archives a GitHub
  repository.** Those are runbook steps.

### Task 2: A configured-but-empty portfolio renders its own state

The Repos panel must not open blank when a token is present and no repos are
tracked. `Configured` (`app/src-tauri/src/panel.rs:34`) models credential
presence only — Unknown / Absent / Present — so "configured, nothing tracked"
currently has no representation and renders as an empty body.

Do this **before** Task 3, or there is a commit in history where first run is
blank.

**Files:**
- Modify: `app/src-tauri/src/github/mod.rs` — `repos_view` at `:445`
- Test: `app/src-tauri/src/github/mod.rs` (inline `#[cfg(test)] mod tests`)

**Interfaces:**
- Consumes: `panel::Configured` (`app/src-tauri/src/panel.rs:34`),
  `GitHubState`, `repos_view(state: &GitHubState, now: DateTime<Utc>) -> Value`
- Produces: `repos_view` emits a `setup` string on the configured-but-empty
  state. Task 3 relies on this being in place.

- [ ] **Step 1: Understand the existing message ladder**

Read `repos_view` at `app/src-tauri/src/github/mod.rs:445-470`. It resolves one
`message` through a four-arm ladder, in deliberate precedence order:

1. `state.credential_error` — outranks the rest, the only one true when set
2. `state.token.is_absent()` → `UNAUTHENTICATED_MESSAGE`
3. `state.health.is_none()` → `REPOS_LOADING_MESSAGE` (no pass has finished)
4. otherwise `None` — render the table

There is **no `repos` field.** An empty portfolio is `health: Some(vec![])` —
a pass that completed and found nothing. That falls through arm 4 to `None`,
so the panel renders a table with zero rows. That is the bug.

The message is published under the `"message"` key as a nested object,
`{ "text": … }` — not a bare string, and not a key called `setup`.

Note also that `message.is_none()` already gates `trailing`, `health`, and the
row list. Adding a fifth arm therefore blanks all of them for free; a separate
early `return` would bypass that and must not be used.

- [ ] **Step 2: Write the failing test**

Add to the `#[cfg(test)] mod tests` block in
`app/src-tauri/src/github/mod.rs` — it is in-module, so private fields are
reachable via `use super::*`. Construct `GitHubState` the way neighboring tests
in that module do.

```rust
#[test]
fn a_finished_pass_with_no_tracked_repos_asks_for_a_repo() {
    let mut state = GitHubState::default();
    state.token = Configured::Present;
    // A completed pass that found nothing — not `None`, which means loading.
    state.apply_repos(Vec::new());

    let vm = repos_view(&state, Utc::now());

    let text = vm["message"]["text"]
        .as_str()
        .expect("a finished pass with nothing tracked must say something");
    assert!(
        text.to_lowercase().contains("repo"),
        "should ask for a repo, got: {text}"
    );
    assert!(
        !text.to_lowercase().contains("token"),
        "the token is present; asking for one again is a lie: {text}"
    );
    assert!(
        vm["rows"].as_array().expect("rows").is_empty(),
        "no rows beside a message"
    );
    assert_eq!(
        vm["loading"], false,
        "a finished pass is not loading"
    );
}
```

- [ ] **Step 3: Run it and confirm it fails**

Run: `cargo test -p devcanopy-app a_finished_pass_with_no_tracked_repos -- --nocapture`
Expected: FAIL — `vm["message"]` is `null`, so indexing `["text"]` yields null
and `.expect(...)` panics.

If it unexpectedly PASSES, the state is already handled. Stop, delete the
duplicate test, and say so in the commit message.

- [ ] **Step 4: Add the message constant**

Beside `UNAUTHENTICATED_MESSAGE` and `REPOS_LOADING_MESSAGE`, matching their
declaration style:

```rust
/// A pass finished and the portfolio is empty. Distinct from
/// `UNAUTHENTICATED_MESSAGE`: the credential is fine, there is simply nothing
/// tracked yet. Telling a user to connect a token they already connected sends
/// them to the wrong screen.
const NO_REPOS_MESSAGE: &str = "No repos tracked yet — add one in Settings → Portfolio.";
```

- [ ] **Step 5: Add the fifth arm to the ladder**

In `repos_view`, after the `state.health.is_none()` arm and before the final
`else`:

```rust
    } else if state.health.as_deref().is_some_and(<[_]>::is_empty) {
        // A finished pass with nothing tracked. Must sit *after* the
        // `is_none()` arm above: `None` is loading, `Some([])` is empty, and
        // collapsing them would make the first frame claim an empty portfolio.
        Some(NO_REPOS_MESSAGE)
```

- [ ] **Step 6: Keep `repos_loading` in agreement**

`repos_loading` documents itself as "the same predicate the message ladder
uses, so the flag cannot disagree with the line the panel is painting."

Read it. Confirm it returns `false` for `health: Some(vec![])` — an empty
portfolio is finished, not loading. If it would now disagree with the ladder,
fix it in this step; the test's `vm["loading"] == false` assertion covers it.

- [ ] **Step 7: Run the test and the full suite**

Run: `cargo test -p devcanopy-app a_finished_pass_with_no_tracked_repos`
Expected: PASS

Run: `cargo test --locked --workspace`
Expected: PASS. Existing `repos_view` tests that build a state with an empty
`health` and expect a table will now see a message — if one fails, it was
asserting the bug. Update it to assert the message.

- [ ] **Step 8: Lint**

Run: `./dev lint`
Expected: clean.

- [ ] **Step 9: Commit**

```bash

git commit -m "fix(repos): a tracked-nothing portfolio says so
```

## Runbook — gated operations

**These are not tasks. Do not automate them.** Every step below is
outward-facing or irreversible: creating a public repository, flipping
visibility, and archiving cannot be undone by a revert, and two of them
publish code to the internet. A human runs these, in order, confirming each.

**The ordering is the security control.** Step 6 must not happen before step 5
passes. A public repository that still references `[self-hosted, …]` is
exploitable for as long as the window is open.

- [ ] **R1. Create `cpmadrid/devcanopy` as PRIVATE.**
  `gh repo create cpmadrid/devcanopy --private`.
  Set `delete_branch_on_merge=true` explicitly — it silently defaults to
  `false` on a new repo.

- [ ] **R2. Push current state as one commit.**
  Export a clean copy of the working tree (no `.git`), `git init` in it, one
  commit, push. Do **not** push an orphan branch from the existing clone — that
  can carry old objects along. Re-point the working clone's `origin` here.

- [ ] **R3. Land Tasks 1-7** on the private repo.

- [ ] **R4. Verify all three CI jobs green** on hosted runners, still private.

- [ ] **R5. Re-run the exposure scan.** Confirm zero hits for `self-hosted`,
  `ubu-3xdv`, `100.87.202.125`, `stsassydog`, `Sassy-Dog/devcanopy`, and
  `secrets.` across the tree.

- [ ] **R6. Flip to public.** ⚠️ Irreversible in practice — assume anything
  published is mirrored within minutes. Requires R4 and R5 to have passed.

- [ ] **R7. Verify first run against a temporary data directory.**
  **Never wipe the real `store.json` or keychain** — they hold every credential
  in daily use. Point the app at a temp data dir and confirm: empty portfolio
  shows the Task 2 setup line, no 404 rows, no container grouping rules.

- [ ] **R8. Create the board.** User-level project under `cpmadrid`, five
  columns (Backlog → Ready → In progress → In review → Done). Carry the 4 open
  issues.

- [ ] **R9. Build the branch ruleset and merge queue by hand.** Required
  contexts: `Rust agent`, `Rust workspace + frontend e2e`,
